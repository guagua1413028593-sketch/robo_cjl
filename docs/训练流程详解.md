## 第 0 站：先建立 4 个概念

强化学习（RL）就四个角色，对应到 RPO 项目里：

| 概念 | 通俗解释 | 在 RPO 里是什么 |
|------|---------|----------------|
| **环境（Environment）** | 机器人所在的"世界" | Isaac Sim 物理仿真器里的 RPO 机器人 + 地面 |
| **智能体（Agent）** | 做决定的"大脑" | 一个神经网络（策略网络），输入观测输出动作 |
| **状态/观测（Observation）** | 大脑"看到"的信息 | 78 个数字：身体倾斜、关节角度、速度指令等 |
| **奖励（Reward）** | 打分 | 走得好 +1 分，乱抖 -0.1 分，摔倒 -200 分 |

训练的本质：**让大脑反复尝试 → 根据打分调整大脑参数 → 打分越来越高**。PPO 就是一种"根据打分调整大脑参数"的算法（第 8 站详解）。

整个训练跑起来就是一句命令：

```bash
python robolab/scripts/rsl_rl/train.py --task=RPO-Flat --headless --logger=tensorboard --num_envs=8192
```

注意 **4096 个机器人同时在仿真里训练**（不是 1 个）——这是 RL 比真人训练快得多的核心原因。4096 个环境 × 每个环境一步 20ms 仿真，一次迭代就积累了 4096×24 ≈ **9.8 万步经验**。

## 第 1 站：启动后发生了什么

入口脚本：`robolab/scripts/rsl_rl/train.py`

1. **启动 Isaac Sim**（`train.py:87`）——一个物理仿真引擎，GPU 上同时模拟几千个机器人
2. **按任务名加载两份配置**（`train.py:234` `@hydra_task_config`）：
   - `env_cfg`：环境长什么样（`robolab/tasks/direct/base/rpo_env_cfg.py` 的 `RPOFlatEnvCfg`）
   - `agent_cfg`：大脑怎么训练（`robolab/tasks/direct/base/agents/rpo_agent_cfg.py` 的 `RPOFlatAgentCfg`）
3. **创建环境** `gym.make("RPO-Flat", cfg=env_cfg)`（`train.py:305`）
4. **包一层适配器** `RslRlVecEnvWrapper`（`train.py:324`）——让 Isaac Lab 环境和 rsl_rl 训练库能对话
5. **创建训练器** `OnPolicyRunner`（`train.py:327`）
6. **开始训练** `runner.learn(num_learning_iterations=12000)`（`train.py:349`）——这就是主循环
7. 训练全程把配置存到 `logs/rsl_rl/rpo_flat/<时间戳>/params/`，模型每 1000 代存一个 `model_N.pt`

> `train.py:355-376` 还有两段"补丁"代码（拦截 setuptools 调用、修复类名解析），是环境兼容性的历史遗留，不影响理解。

## 第 2 站：机器人怎么进入仿真

机器人定义：`robolab/robolab/assets/robots/roboparty.py` 的 `RPO_CFG`（`roboparty.py:39`）

**身体**：从一个 **URDF 文件**加载（`robolab/data/robots/roboparty/rpo/urdf/rpo.urdf`）。URDF 是机器人的"零件清单"：每个连杆的长、质量、惯量，关节怎么连接。

**23 个关节**（可以动的"马达"），左右对称：
- 每条腿 6 个：thigh_yaw / thigh_roll / thigh_pitch（大腿三个方向）、knee（膝）、ankle_pitch / ankle_roll（踝两个方向）
- 每条手臂 5 个：arm_pitch / arm_roll / arm_yaw、elbow_pitch / elbow_yaw
- 躯干 1 个：torso

**关节怎么动——PD 控制**（`roboparty.py:82-153`）：策略网络输出的动作其实是**目标关节角度**。关节由 PD 控制器驱动：

```
力矩 = 刚度(kp) × (目标角 − 当前角) − 阻尼(kd) × 当前角速度
```

就像弹簧拉着关节往目标角度走：

| 关节组 | kp | kd | 力矩上限 | 备注 |
|--------|-----|-----|---------|------|
| 腿（thigh ×3 + knee + torso） | 100 / 150（knee、torso） | 3.3 / 5.0 | 120 N·m | 强壮 |
| 脚踝（ankle ×2） | 40 | 2.0 | 27 N·m | 软 |
| 肩（arm ×3） | 40 | 2.0 | 27 N·m | |
| 肘（elbow ×2） | 30 / 20 | 1.5 / 1.0 | 27 N·m | 最软 |

细节：所有关节用 `DelayedPDActuatorCfg`，仿真里电机指令有 **0~2 步随机延迟**——模仿真实电机的通信延迟，让策略对延迟鲁棒。

**初始姿势**（`roboparty.py:63-80`）：机器人出生在 z=0.75 米，微微下蹲（大腿 −0.1、膝盖 0.3、踝 −0.2 弧度），手臂自然弯曲。

## 第 3 站：环境怎么运转

环境主逻辑：`robolab/robolab/tasks/direct/base/base_env.py`

RL 的核心循环在 `step()` 函数（`base_env.py:192`）：

```
策略给出动作(23个数)
   ↓
① 动作处理：clip → ×0.25(action_scale) → +默认关节角度（base_env.py:245-249）
   ↓
② 物理仿真 4 次（decimation=4，每次 0.005s）（base_env.py:199-206）
   ↓  ← 一共前进 0.02s（50Hz 控制频率）
③ 更新速度指令（每10秒换一次指令）（base_env.py:210）
④ 检查是否摔倒/超时 → 需要重置的机器人重新出生（base_env.py:214-222）
⑤ 计算奖励（base_env.py:216）
⑥ 计算观测（base_env.py:224）
   ↓
把 观测+奖励+是否终止 打包交给 PPO
```

关键数字：**控制频率 50Hz**（0.02s 一步），**一个回合 20 秒** = 1000 步。

**速度指令**（`base_env.py:64-74`）：训练时机器人不是随便走，而是被命令"往前走 1.0 m/s"或"左转 0.5 rad/s"。指令每 10 秒随机换一次（`base_config.py:124-131`）：

| 指令范围 | 值 |
|---------|-----|
| 前进 lin_vel_x | −0.6 ~ 1.0 m/s |
| 横移 lin_vel_y | ±0.5 m/s |
| 转向 ang_vel_z | ±1.57 rad/s |
| 原地站立概率 | 20% |

RL 训练的核心技巧之一：让机器人学会听懂指令，你才能控制它。

## 第 4 站：机器人"看到"什么

观测在 `compute_current_observations()`（`base_env.py:146`）。大脑（actor）每步收到 **78 个数字**：

| 内容 | 维度 | 说明 |
|------|------|------|
| 角速度 | 3 | 身体转得多快 |
| 重力投影 | 3 | **身体往哪个方向倾斜**（最重要的本体感觉） |
| 速度指令 | 3 | 主人让我往哪走、多快 |
| 关节角度（相对默认姿势） | 23 | 每条腿弯成什么样 |
| 关节角速度 | 23 | 关节动得多快 |
| 上一步的动作 | 23 | 自己刚才干了什么 |

**历史缓冲**（`base_env.py:139-144`）：不止看当前这一帧，而是**最近 10 帧**（0.2 秒）摞起来一起看 → 实际输入 780 维。因为只看一帧无法知道速度、趋势，就像你看一张照片看不出车在往哪开，看 10 帧连续照片就能。

**噪声**（`base_env.py:256-257`）：观测里还加了随机噪声——模拟真实传感器的误差，让策略不"玻璃心"：

| 噪声项 | 幅度（均匀分布） |
|--------|-----------------|
| 角速度 | 0.2 |
| 重力投影 | 0.05 |
| 关节角 | 0.01（Flat 0.03） |
| 关节速度 | 1.5（Flat 1.75） |

**Value 网络（critic）看更多**（`base_env.py:185-186`）：139 维 = 78 维 + 线速度(3) + 脚接触状态(2) + 接触力(6) + 腾空时间(2) + 离地高度(2) + 关节加速度(23) + 关节力矩(23)。这些是仿真里才能精确拿到的"**特权信息**"，只给打分员（critic）看，不给大脑（actor）看——因为**真机上拿不到**这些信息。

> 一句话：actor 只用真机上能测到的信息（否则 sim2real 会崩），critic 可以开挂。

## 第 5 站：奖励——训练的灵魂

奖励定义：`robolab/robolab/tasks/direct/base/rpo_env_cfg.py:60-170`，具体公式实现在 `robolab/robolab/tasks/direct/base/mdp/rewards.py`。每 0.02 秒环境给一个奖励，所有项加权求和。

**核心目标（正向）：**

| 奖励项 | 权重 | 意思 |
|--------|------|------|
| 线速度跟踪 | +1.0 | 走的速度越接近指令越好（高斯函数，差 0.5 m/s 就衰减） |
| 角速度跟踪 | +1.0 | 转向越接近指令越好 |
| 腾空时间（脚） | +0.25 | 鼓励走路时脚离地（双足机器人特有） |
| 站立时脚接触 | +0.1 | 没指令时乖乖站着 |
| 身体朝上 | +0.4 | 保持直立 |
| 脚间距 / 膝间距 | +0.1 / +0.1 | 两条腿别并太拢也别劈太开（0.16~0.50 m / 0.18~0.35 m） |
| 脚离地高度 | +0.2 | 走路时脚抬到合适高度（射线传感器测量） |

**风格修正（负向惩罚，让动作像人）：**

| 奖励项 | 权重 | 意思 |
|--------|------|------|
| 摔倒 | **−200** | 一票否决 |
| 乱碰身体 | −1.0 | 手碰到腿/躯干（触觉传感器，除脚踝外的所有身体） |
| 身体倾斜 | −1.0 | 保持竖直 |
| 能量消耗 | −1e-4 | 省电 |
| 关节力矩 | −1e-5 | 省力 |
| 关节速度 | −2e-4 | 别乱甩 |
| 关节加速度 | −2.5e-7 | 动作平滑 |
| 动作变化率 / 平滑度 | −0.02 / −0.02 | 别突然乱动 |
| 脚打滑 | −0.3 | 脚别在地上蹭 |
| 脚冲击力 | −3e-3 | 落地别太重（阈值 500 N） |
| 脚绊倒 | −1.0 | 别踢到自己 |
| 脚朝向 | −0.1 | 脚底板保持水平 |
| 关节越界 | −1.0 | 别撞限位 |
| 髋（thigh yaw/roll）偏离 | −0.03 | 髋部别乱摆 |
| 躯干+手臂偏离默认姿势 | −1.0 | **手臂别乱甩，保持自然姿势** |
| 腿偏离默认姿势 | −0.01 | 腿的默认姿势偏差 |

**看懂这张表你就懂了机器人 RL 的核心痛点**：光说"往前走"是不够的，机器人会找到各种作弊姿势（拖着脚滑行、像螃蟹一样横挪、疯狂甩手）。所以要用一堆小惩罚项"修剪"它的行为，把它逼进**自然的、可迁移到真机的**步态空间。这就是为什么奖励函数有 20 多项。

## 第 6 站：什么时候重来

终止判定：`base_env.py:288-307` 的 `_get_dones()`。

### RPO-Flat / RPO-Rough 实际生效的终止条件

#### ✅ 1. 摔倒（接触终止）—— 生效

**碰哪些部位**（`rpo_env_cfg.py:193`）：

```python
self.robot.terminate_contacts_body_names = ["torso_link", ".*_thigh_yaw_link", ".*_thigh_roll_link"]
```

共 **5 个连杆**：躯干 + 左/右大腿 yaw + 左/右大腿 roll。

**力度阈值**（硬编码在 `base_env.py:290-301`）：接触力 > **1.0 N** 就判摔倒。两点细节：
- 1 N ≈ 102 克物体的重量，所以实际语义就是"**这些部位只要沾到地面就算摔倒**"
- 检查的是接触传感器**最近 3 个物理步**的历史窗口（`scene_cfg.py:79` `history_length=3`，每物理步 5ms → 15ms 窗口），所以哪怕只是"擦"了地面一下也会触发

#### ❌ 2. 翻倒（身体倾斜）—— 实际关闭

判断逻辑在 `base_env.py:302-303`：

```python
if self.cfg.robot.terminate_base_orientation is not None:
    terminated_buf |= torch.acos(-projected_gravity_b[:, 2]).abs() > self.cfg.robot.terminate_base_orientation
```

`terminate_base_orientation` 在 `base_config.py:91` 默认 `None`，全仓库没有任何地方赋值 → 检查被跳过。

#### ❌ 3. 掉太低（质心高度）—— 实际关闭

同理，`base_env.py:304-305` 的检查依赖 `terminate_base_height`（`base_config.py:90`，默认 `None`），从未被赋值 → 关闭。

#### ✅ 4. 超时 —— 生效

`base_env.py:87`：`episode_length = ceil(20.0 s / 0.02 s) = 1000 步`（20 s 定义在 `base_config.py:266`，0.02 s = decimation 4 × dt 0.005）。

**所以 RPO-Flat/Rough 实际只有两个终止条件：5 个连杆碰地（>1N），或走满 1000 步。** 倾斜/高度检查没开启是设计选择——躯干和大腿碰地已覆盖绝大多数摔倒姿态。

如需开启，在 `rpo_env_cfg.py` 的 `RPOFlatEnvCfg.__post_init__` 加两行：

```python
self.robot.terminate_base_orientation = 1.047  # 60° = 1.047 弧度
self.robot.terminate_base_height = 0.3          # 质心低于 0.3m 判死
```

### 管理器系列（AMP / Parkour）的终止阈值对比

| 条件 | RPO-AMP（`amp_env_cfg.py:412-423`） | RPO-Parkour（`parkour_env_cfg.py:638-648`） |
|------|------|------|
| 接触终止 | 接触力 > **1.0 N**（身体列表在 `rpo_amp_env_cfg.py:264`） | 只查 `torso_link`，> **1.0 N** |
| 倾斜 | **60°**（`math.radians(60.0)`） | **1.0 弧度 ≈ 57.3°** |
| 高度 | 质心 < **0.2 m** | 质心 < 环境原点上方 **0.5 m** |
| 超时 | 20 s（默认） | 20 s（默认） |
| 其他 | — | 跑出地形边界（缓冲区 2 m），标了 `time_out=True`，**按超时处理而不是失败** |

`RPO-Interrupt` / `RPO-AttnEnc` 额外把手臂、肘部连杆加入终止接触列表（`rpo_interrupt_env_cfg.py:276`、`rpo_attn_enc_env_cfg.py:218`）——这两个任务里手臂碰地算失败。

### 重置

重置逻辑：`base_env.py:309-342` 的 `_reset_idx`。机器人**随机换出生姿势**（`base_config.py:211-233`）：
- 位置随机偏移 ±0.5 m，偏航随机 ±π
- 关节角度按 0.5~1.5 倍缩放
- 初始速度随机（±0.5 m/s，角速度 ±0.52 rad/s）

这样它摔倒后能在任何状态下重新站起来。另外 `learn(init_at_random_ep_len=True)`（`on_policy_runner.py:65-68`）会把所有环境的回合长度打乱——避免 4096 个机器人齐步走、同时摔倒、同时重置（节奏共振）。

## 第 7 站：域随机化

配置：`base_config.py:150-248` 的 `EventCfg`。

RL 最大的坑：**仿真里练得好 ≠ 真机上走得好**。对策是"域随机化"——每批机器人出生时物理参数都不同：

| 随机化 | 范围 | 时机 |
|--------|------|------|
| 地面摩擦 | 0.3 ~ 1.6（从冰面到橡胶地） | startup |
| 躯干质量 | ±3 kg | startup |
| 质心偏移 | ±2.5 cm（x/y）、±5 cm（z） | startup |
| 四肢质量缩放 | ×0.9 ~ 1.1 | startup |
| 电机刚度/阻尼 | ×0.9 ~ 1.1 | startup |
| 电机电枢惯量 | ×0.5 ~ 1.5 | startup |
| 随机推搡 | 每 10~15 秒推一把（±0.5 m/s） | interval |

原理：**如果一个策略在 4096 种不同物理参数下都能走好，那真实世界大概率也落在它见过的分布里。** 随机推搡则训练抗干扰恢复能力。

## 第 8 站：PPO 怎么学

训练主循环：`rsl_rl/rsl_rl/runners/on_policy_runner.py:82-133`；算法实现：`rsl_rl/rsl_rl/algorithms/ppo.py`。

12000 次迭代，每次迭代分两阶段：

### 阶段 A：收集经验（rollout）（`on_policy_runner.py:85-105`）

```
重复 24 步（num_steps_per_env=24）：
    大脑采样动作 act(obs)      → 高斯分布里采样（带随机性=探索）
    环境走一步 env.step(action)
    记录 (obs, action, reward, done) 存进 RolloutStorage
```

共 4096×24 ≈ 9.8 万条经验。注意这时大脑**不学习**，只收集。

### 阶段 B：学习（update）（`ppo.py:196-432`）

**第一步，算每条经验"有多好"——GAE 优势函数**（`ppo.py:173-194`）：
- 价值网络 V(s) 预估"从这状态开始未来能拿多少分"
- 实际拿到的分和预估的差距 = "惊喜" = 优势 A。**优势 > 0 说明这步走得比预期好，应该多这样做**
- 超时（走满 20 秒）不算失败，用 V 值续上（`ppo.py:162-166`），否则机器人会学到"活到 20 秒就自杀"

**第二步，更新大脑参数**（`ppo.py:213-402`）：把 9.8 万条经验分成 4 小批，**反复学 5 遍**（epochs），每次用三个损失函数调参：
- **策略损失（surrogate）**：`ratio = 新策略概率 / 旧策略概率`，优势 A 加权。关键是 **clip 到 [0.8, 1.2]**（`ppo.py:298-303`）——每次更新步子别太大，防止一次学崩（这就是 PPO 名字里 "Proximal" 的由来）
- **价值损失**：让 V(s) 预测得更准
- **熵奖励**：鼓励大脑保持一定随机性，别过早收敛到坏习惯

**自适应学习率**（`ppo.py:261-295`）：每批更新前算新旧策略的 KL 散度（差多远），差太多 → 学习率 ÷1.5，太保守 → ×1.5（范围 [1e-5, 1e-2]）。自动找安全的学习速度。

之后回到阶段 A 用**新大脑**继续收集经验……循环 12000 次。

**量级感受**：12000 迭代 × 9.8 万步 ≈ **11.8 亿步**经验 ≈ 4096 个机器人合计约 273 天的"机器人寿命"（并行压缩到几天墙钟时间）。

## 第 9 站：网络结构与超参数

配置：`robolab/robolab/tasks/direct/base/agents/rpo_agent_cfg.py:160-189`。

**网络结构**：Actor-Critic（演员-评论家）架构，两个 MLP：

- **Actor（演员）**：780 维观测 → [512 → 256 → 128]（ELU 激活）→ 输出 23 维动作的高斯分布均值+标准差。**动作 = 从这分布采样**（随机性就是探索）
- **Critic（评论家）**：1390 维观测 → 同样的 [512,256,128] → 输出 1 个数 V(s)（这状态值多少分）

**关键超参数速查表**：

| 超参 | 值 | 通俗含义 |
|------|-----|---------|
| num_steps_per_env | 24 | 每次迭代收集多少步经验 |
| max_iterations | 12000 | 学多少轮 |
| learning_rate | 1e-3 | 每次调参的步子（自适应调节） |
| clip_param | 0.2 | 步子最大 20% |
| gamma | 0.99 | 未来奖励的折扣（看得比较远） |
| lam | 0.95 | GAE 的平滑系数 |
| entropy_coef | 0.005 | 保留 0.5% 的"好奇心" |
| num_learning_epochs / mini_batches | 5 / 4 | 每批经验学 5 遍，分 4 小块 |
| desired_kl | 0.01 | 自适应 LR 的目标变化幅度 |
| max_grad_norm | 1.0 | 梯度裁剪，防爆炸 |
| init_noise_std | 1.0 | 初始探索程度 |
| seed | 42 | 随机种子（实验可复现） |
| save_interval | 1000 | 每 1000 代存一个模型 |

**镜像对称**（RPO-Rough 开启，`rpo_agent_cfg.py:213-218`）：机器人左右对称，把经验镜像一下（左腿数据变右腿）就凭空多一倍数据，还加镜像一致性损失（权重 0.2）——免费的午餐。镜像索引/符号表在 `rpo_agent_cfg.py:49-156`。

## 第 11 站：怎么评估训练好的模型

训练时的奖励有噪声、有随机性，不能直接当成绩。评估协议（`HANDOFF.md` + `robolab/scripts/tools/co_design_eval.py`）：

```
固定指令 → 确定性 rollout（关噪声、不推搡、平地、seed=42）
三个指令：0.5 m/s 前进 / 1.0 m/s 前进 / -0.5 m/s 后退
每个指令跑 20 秒，算累计回报 → 取平均
```

**为什么三指令平均？** 训练时 20% 是站立指令，单测一个速度会高估。

**重要教训（HANDOFF 核心发现）**：co-design 实验里 3000 代时所有方案都没收敛，BO 排名是"噪音排名"；跑到 12000 代后原始腿长反超所有修改方案（原始腿长 3000 代排第 10 → 12000 代排第 1）。**评估一定要在收敛之后做。**

## 任务名速查（Flat / Rough / AMP 都是什么意思）

**算法都是 PPO 家族**：RPO-Flat/Rough/AttnEnc/Interrupt/BeyondMimic 用标准 PPO（`class_name="PPO"`），RPO-AMP/Parkour 用 PPOAMP（PPO 子类，多一个判别器，`rsl_rl/algorithms/ppo_amp.py`）。不同任务换的不是算法，而是环境（观测/奖励/终止）+ 网络结构。

| 任务名 | 全称/含义 | 中文解释 | 一句话理解 | 不用相机可部署 |
|--------|-----------|---------|-----------|---------------|
| **RPO-Flat** | flat ground | 平地 | 基础任务：平地上听懂速度指令走路 | ✅ |
| **RPO-Rough** | rough terrain | 崎岖地形 | 楼梯/斜坡/乱石地走路；给 critic 加 187 维"高度扫描"特权信息（真机拿不到的上帝视角）；开启镜像对称增广 | ✅（actor 不看高度） |
| **RPO-AttnEnc** | attention encoder | 注意力编码器地形 | Rough 的"可上真机版"：高度扫描改走**可学习的注意力编码器**，actor 也能看到 | ❌ 需深度/测距传感器 |
| **RPO-Interrupt** | interrupt | 手臂抗扰动 | 平地上随机"打断"手臂 8 个关节（扰动概率课程 0→0.5），练手臂的抗干扰能力 | ✅ |
| **RPO-AMP** | Adversarial Motion Priors | 对抗运动先验 | 加一个"裁判"（判别器）鉴别动作像不像真人动捕，用风格奖励把步态逼向人类 | ✅（判别器仅训练用） |
| **RPO-BeyondMimic** | beyond mimicry | 全身动作复刻 | 不发抽象奖励，直接下指令"复刻这段动捕片段"（如从躺到站） | ✅ |
| **RPO-Parkour** | parkour | 跑酷 | AMP + 噪声深度相机，让机器人"看路"跑酷 | ❌ 需深度相机 |
| **`-Play` 后缀**（如 RPO-AMP-Play） | play | 演示配置 | 同一个任务的**播放/演示版**（1×1 地形、关随机化），用来看效果，不用于训练 | — |

### 任务之间的关系

```
                    RPO-Flat（基础：平地走路）
                         │
   ┌──────────┬──────────┼──────────────┬──────────────┐
   ▼          ▼          ▼              ▼              ▼
RPO-Rough  RPO-Interrupt  RPO-AMP  RPO-BeyondMimic
（+崎岖地形   （+手臂随机   （+运动风格    （动作复刻线）
 +特权高度扫描 扰动课程）    判别器）          │
 +对称增广）                 │              └─ RPO-Getup-Mimic（起身动作）
   │                        ▼
   └─ RPO-AttnEnc       RPO-Parkour
      （可上真机版）      （AMP + 深度相机）
```

- 底层都是同一个 RPO 机器人（23 关节），同一个 `RPO_CFG`
- 每个任务独立训练出一个策略，checkpoint 分别存在 `logs/rsl_rl/rpo_flat/`、`rpo_rough/` 等目录下，策略之间不能通用（观测维度、奖励都不一样）
- 学习建议从 RPO-Flat 入手——它是一切的基础

### 哪些策略可以部署到真机（不用相机）

**核心设计原则——非对称 Actor-Critic**：actor 只允许看"真机上能测到的信息"（IMU + 关节编码器 + 指令），critic 才能在训练时"开挂"看特权信息（线速度、接触力、高度扫描等）。所以判断能否部署只看 **actor 的输入**。

| 可部署性 | 任务 | 说明 |
|---------|------|------|
| ✅ 不用相机 | RPO-Flat | actor 输入 78 维 = IMU(6) + 指令(3) + 关节编码器(46) + 上一步动作(23)，真机全有 |
| ✅ 不用相机 | RPO-Rough | 高度扫描只进 critic（特权信息），actor 仍是 78 维——部署时和 Flat 完全一样，靠本体感觉在崎岖地形上"盲走" |
| ✅ 不用相机 | RPO-Interrupt | 79 维 = 78 + 1 个打断标志位；真机上标志恒为 0 |
| ✅ 不用相机 | RPO-AMP | 判别器只在训练时存在；部署时只用 actor，输入和 Flat 同构 |
| ✅ 不用相机 | RPO-BeyondMimic / Getup-Mimic | 输入 = 动作片段指令 + 本体感觉 |
| ❌ 需深度/测距传感器 | RPO-AttnEnc | 高度扫描进了 actor（`rpo_attn_enc_env_cfg.py:210` `enable_height_scan_actor=True`，经注意力编码器）→ 真机需深度相机或激光测距 |
| ❌ 需深度相机 | RPO-Parkour | 8 帧深度图历史 + CNN 编码器 |

部署时还需保证：同样的观测计算（IMU 安装位置、关节零点 = default_joint_pos）、50 Hz 控制、PD 增益一致——sim2sim 脚本（`robolab/scripts/mujoco/`）里硬编码了这些约定，是上真机前的对照检查。

### 单任务还是多任务？

- **训练产物层面**：每个任务一个独立策略，互不通用。
- **技能层面**：多数是"一个技能 + 连续指令输入"（command-conditioned）。速度指令是观测的一部分，所以 Flat 一个策略就能前/后/横/转/站连续可调——这叫指令泛化，不算多任务。
- **真正的多任务 RL**（一个网络掌握多个独立技能，通常需要 task ID 输入）仓库里目前没有。
- **特例**：AMP = 单一"带风格行走"技能（动捕数据集混合多片段，但奖励目标单一）；BeyondMimic = 一个策略跟踪一个动作片段（walk 与 getup 是两个独立任务）；Parkour = 最接近多地形泛化，但奖励目标仍是速度跟踪。
- **合并多技能的正路**：混合地形/扰动课程训练 + 必要时给 actor 加感知（AttnEnc/Parkour 路线），而不是部署多个策略做集成。

## 学习路径建议

1. **先跑一次小规模训练**感受全流程：
   ```bash
   python robolab/scripts/rsl_rl/train.py --task=RPO-Flat --num_envs=256 --max_iterations=50 --headless --logger=tensorboard
   ```
